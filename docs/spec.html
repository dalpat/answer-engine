01Vision & guiding principles

What we're building and the rules that settle every downstream choice.

An answer engine, not a chatbot. Every query runs the loop search → read → synthesize with inline citations. Plain chat is simply the mode where the search step is skipped, so it comes for free. The product feels like a research companion: ask, get a cited answer, ask a follow-up in context, explore suggested questions.

Guiding principles

  • Self-hosted by default. No external service unless there is genuinely no alternative. No SaaS platform lock-in (this is why we rejected Next.js/Vercel and hosted auth/search).
  • Own the code. Prefer code that lives in our repo over black-box dependencies — especially for auth.
  • Pleasant & maintainable. Code should read well any day, any time. This is a stated, weighted value — it decided the framework.
  • Launch-ready, not enterprise-bloated. A hobby project that's polished and shippable — but we skip security/ops theater that only matters for a public, static-IP deployment we don't have.
  • BYOK. Users bring their own OpenAI-compatible endpoints and keys; we stay provider-agnostic.

The whole pipeline reads top-to-bottom in one +server.ts file — the concurrent fan-out is a Promise.all, and the endpoint returns the stream.

// src/routes/api/ask/+server.ts  (shape)
export async function POST({ request, locals }) {
  const { query, threadId, connectionId } = await request.json();
  return streamSSE(async (emit) => {
    emit('status', { phase: 'understanding' });
    const queries = await rewrite(query);            // 1
    emit('status', { phase: 'searching', queries });
    const links = dedupe(await Promise.all(queries.map(searxng))); // 2,3
    emit('status', { phase: 'reading' });
    const pages = await Promise.all(links.map(extract));          // 4
    emit('sources', pages.map(toCard));
    emit('status', { phase: 'answering' });
    for await (const tok of synthesize(query, pages, llmFor(connectionId)))
      emit('token', tok);                                          // 5
    emit('related', await relatedQuestions(query));                // 6
    emit('done');
  });
}

05Search loop intelligence

Smart enough to fix vague questions; simple enough to debug.

Now — rewrite + fan-out + single synthesis. The LLM turns the user's (possibly vague or conversational) question into 1–3 targeted search queries, run in parallel against SearXNG. Results are deduped and ranked, top 5–10 extracted, then a single synthesis pass produces the cited answer.

Why not single-shot: it feels broken the instant someone types a vague question. The rewrite is one cheap call that massively lifts relevance, and parallel fan-out costs no extra wall-clock.
Why not agentic now: a search/read/loop is better for hard questions but multiplies latency, token cost, and failure modes (wandering loops, no clean termination). It's the wrong default — perfect as a later "Deep Research" toggle, added as a branch in askLoop().

Follow-up context

On a follow-up, we feed back prior Q&A summaries, not full source text — keeps the thread coherent while bounding token cost.

07Citations & answer rendering

Sources are numbered in the synthesis prompt; the model is instructed to cite n. Each marker renders as a clickable chip that scrolls to / highlights its source card.

The Sony A7 IV leads in low light 1, while the Fuji X-T5 wins on color science 2 and portability 3.

  • Source cards: favicon + domain + title, docked above the answer.
  • Rendering: markdown with code blocks, tables, and lists.
  • Honest caveat: models occasionally mis-cite. Acceptable and prompt-improvable; the trust value far outweighs the imperfection.

08BYOK model configuration

The "our own OpenAI-compatible model" core. Multiple backends, one-tap switching, no friction.

Connections

Users add named connections, each with a base URL + key + auto-loaded model list:

  • local vLLM · http://localhost:8000
  • Groq · api.groq.com
  • Together · api.together.xyz

Frictionless setup

  • Auto model list via GET /v1/models → dropdown. No typing IDs.
  • Fallback: manual entry only if an endpoint lacks /models.
  • Test-on-save: one cheap call → instant ✓ works instead of a cryptic mid-query failure.
  • Composer switcher: pick the active model per thread, inline.

Launch keeps tuning minimal — temperature only. Per-model parameter UIs are later polish.

09Auth & security

Own-your-code auth (Lucia pattern)

Not hand-rolled crypto and not a black-box package — the Breeze/Fortify analog for SvelteKit: ~150 lines of session/cookie code in src/lib/server/auth, built on vetted primitives (@node-rs/argon2 for hashing, Web Crypto for tokens). Email + password, session cookies, in our repo, fully owned. OAuth (GitHub/Google) is an optional add-on, never a hard dependency.

Key encryption at rest

Per-user LLM keys are AES-GCM encrypted with a single server ENCRYPTION_KEY env before they touch the DB. We're holding other people's credentials — this is table stakes, deliberately distinct from the "enterprise nonsense" we skip.

Deliberately skipped (local-only): TLS termination, SSRF guards on the fetcher, and rate limiting. These only matter for a public, static-IP deployment. Documented as drop-in additions for "if you ever go public" — not built now.

10Data model

Drizzle schema, portable types only (clean SQLite→Postgres swap).

users        ( id, email, password_hash, created_at )
sessions     ( id, user_id, expires_at )
connections  ( id, user_id, name, base_url, key_encrypted, default_model )
threads      ( id, user_id, title, created_at )
messages     ( id, thread_id, role, content,           // role: user | assistant
               connection_id, created_at )
sources      ( id, message_id, n, url, title, domain,  // n = citation number
               favicon, snippet )
related      ( id, message_id, question )               // suggested follow-ups

Keep to portable types — no SQLite-absent uuid/jsonb — so the Postgres swap is just a driver + connection string change.

11Packaging & deploy

One command on your machine. Two services, file-based DB, localhost.

# docker-compose.yml  (shape)
services:
  app:
    build: .                       # SvelteKit adapter-node
    ports: ["3000:3000"]
    environment:
      - DATABASE_URL=file:/data/app.db     # → postgres://… to upgrade
      - ENCRYPTION_KEY=${ENCRYPTION_KEY}
      - SEARXNG_URL=http://searxng:8080
    volumes: ["./data:/data"]
  searxng:
    image: searxng/searxng
    environment: [ "SEARXNG_BASE_URL=http://localhost:8080" ]

# run:  docker compose up   →   open http://localhost:3000

DB upgrade path: flip DATABASE_URL to a Postgres URL and add a postgres service. Same Drizzle schema.

12MVP scope & later

Built & verified

  • Search → read → cited answer loop (rewrite + fan-out)
  • Animated 4-phase live progress stepper
  • Inline n citations + source cards
  • Persistent threads + multi-turn follow-ups in context
  • Multi-user auth (own-code) + encrypted BYOK keys
  • Multi-connection setup, auto model list, composer switcher
  • Deep Research toggle (extra gap-filling round)
  • Playwright fallback (optional, behind EXTRACT_BROWSER=1)
  • Drizzle migrations auto-apply on boot; docker-compose

Deferred by design

  • Agentic multi-step Deep (current = single extra round)
  • True Postgres (pg-core fork; remote libSQL/Turso is a drop-in URL swap)
  • OAuth social login
  • Shareable answer links
  • Public hardening: TLS, SSRF guard, rate limiting
  • Per-model parameter tuning UI
